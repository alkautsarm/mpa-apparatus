# Internationalization (i18n)

This project uses [react-i18next](https://react.i18next.com/) for internationalization. Two locales ship out of the box: English (`en`) and Indonesian (`id`).

## How it works

`initI18n()` in `src/shared/lib/i18n/index.ts` initializes i18next once per page load. Each module calls it at the top of `main.tsx` before mounting:

```ts
import { initI18n } from "@/shared/lib/i18n";
initI18n();
```

Language is detected from `localStorage` first, then the browser's `navigator.language`. The detected language is persisted back to `localStorage` under the key `i18nextLng`. Falls back to `en` when no match is found.

## Namespace conventions

Translations are split by module namespace to mirror module isolation:

| Namespace  | File path                                  | Used by                  |
|------------|--------------------------------------------|--------------------------|
| `common`   | `src/shared/lib/i18n/locales/{lang}/common.json` | cross-module shared strings |
| `auth`     | `src/shared/lib/i18n/locales/{lang}/auth.json`   | `src/modules/auth/`      |
| `home`     | `src/shared/lib/i18n/locales/{lang}/home.json`   | `src/modules/home/`      |

Use `useTranslation('auth')` inside auth pages, `useTranslation('home')` inside home pages, etc.

## Zod validation messages

Zod's built-in error messages (required, invalid email, too short, etc.) are automatically translated via [`zod-i18n-map`](https://github.com/aiji42/zod-i18n-map). The error map is set globally inside `initI18n()` — no extra configuration needed per schema.

For `.refine()` custom messages, use `i18next.t()` directly (imported from `@/shared/lib/i18n`):

```ts
import i18next from "@/shared/lib/i18n";

const schema = z.object({ ... }).refine(
  (data) => data.password === data.confirmPassword,
  { message: i18next.t("auth:validation.passwordMismatch"), path: ["confirmPassword"] }
);
```

> **Init order**: `initI18n()` must run before any `.refine()` message using `i18next.t()` is evaluated. Calling it at the top of `main.tsx` before `createRoot` guarantees this.

## Adding a new locale

1. Create `src/shared/lib/i18n/locales/<lang>/common.json`, `auth.json`, `home.json` (copy from `en/` as a starting point)
2. Add the new locale to the `resources` object in `src/shared/lib/i18n/index.ts`

`zod-i18n-map` ships translations for many locales — check `node_modules/zod-i18n-map/locales/` for availability. Import and register the matching `zod.json` alongside your other locale files.

## Adding a new module

Create `src/shared/lib/i18n/locales/en/<module>.json` and `id/<module>.json`, then register them in the `ns` array and `resources` object in `src/shared/lib/i18n/index.ts`. Use `useTranslation('<module>')` in the module's pages.

## Bundle size

`i18next` + `react-i18next` + `i18next-browser-languagedetector` adds approximately **30 KB gzipped** to each module bundle. Translation JSON files are bundled eagerly (no lazy-loading) — for 2 locales with small files this is negligible.

## Switching language at runtime

```ts
import i18next from "@/shared/lib/i18n";
i18next.changeLanguage("id");
```

The new language is persisted to `localStorage` automatically and takes effect immediately across all mounted components.
